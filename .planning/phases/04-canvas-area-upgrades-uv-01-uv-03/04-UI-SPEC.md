### Active Tool Color Identity Contract (UV-01)

| Tool | State | box-shadow color | border-color | Note |
|------|-------|-----------------|--------------|------|
| `tool-draw` (.active) | Active | `--nexus-blue` (#00d7ff) — strong neon glow | `rgb(0 215 255 / 40%)` | Root `.tool-draw` scope |
| `tool-erase` (.active) | Active | `#ff3b3b` — red neon glow | `rgb(255 59 59 / 40%)` | Root `.tool-erase` scope |
| `placeImage` (.active) | Active | `#b366ff` — purple neon glow | `rgb(179 102 255 / 40%)` | Root-scope or direct; matches layers panel |
| `placeText` (.active) | Active | `--nexus-blue` (cyan) — same as draw | `rgb(0 215 255 / 40%)` | Text = same family as draw tools |
| `select` (.active) | Active | `rgb(255 255 255 / 20%)` neutral | `rgb(255 255 255 / 25%)` | Neutral — selector has no strong semantic |

**Glow intensity spec:** Strong neon — `box-shadow: 0 0 14px {color} / 60%, 0 0 4px {color} / 80%` pattern. Stronger than the existing generic `--primary-glow-medium` (which is only 10px / 45%). This is intentional — per-tool active state must be visually unmissable at a glance.

**Accent reserved for:** active tool state indicator ONLY (one tool at a time). NOT used for hover, focus rings, or any other interactive elements.

**Dominant (60%):** `--nexus-dark` (`#0b0f14`) — all backgrounds, surfaces.
**Secondary (30%):** `rgb(255 255 255 / 3-6%)` — card/panel surfaces (`--bg-elevated`, `--border-color`).
**Accent (10%):** per-tool neon color — active tool button only.
**Destructive:** `#ff3b3b` — reserved for erase tool active state (semantic alignment).

### Checkerboard (UV-03)

| Property | Value | Rationale |
|----------|-------|-----------|
| Technique | `::before` pseudo-element on `.viewport-canvas` | No JSX required; canvas keeps all its rules untouched |
| Pattern | `conic-gradient(#141a20 25%, #1c242e 25% 50%, #141a20 50% 75%, #1c242e 75%)` single declaration | Exactly one conic-gradient layer (success criteria 2) |
| Tile size | `background-size: 10px 10px` | Discrete enough not to compete with image content |
| z-index | `0` | Below canvas (z-index 1100 per existing rule) |
| pointer-events | `none` | Never intercepts events (success criteria 3) |
| Positioning | `position: absolute; inset: 0` | Fills viewport-canvas exactly |
| Debug bg removal | `.uv-editor-viewport canvas { background-color: transparent }` | Replaces `rgb(10 10 10 / 60%)` — same selector, override |
| Performance-mode | Checkerboard `::before` hidden: `body.performance-mode .viewport-canvas::before { display: none }` | Heavy gradient suppressed (user decision) |

Checkerboard tones: `#141a20` (very dark navy) / `#1c242e` (slightly lighter navy) — both in the `--nexus-dark` family. Discrete; does not compete with any image color.

## Component Interaction Contract

### Tool Dock Buttons (UV-01)

**Base state** (`.tool-button`, no `.active`): unchanged — `background: rgb(var(--nexus-dark-rgb), 0.45)`, `border: 1px solid rgb(255 255 255 / 3%)`.

**Active state per tool** — additive rules scoped to root tool class:

```
.uv-editor-panel.tool-draw  .uv-tools-dock .tool-button[title="Desenhar"].active  → cyan glow
.uv-editor-panel.tool-erase .uv-tools-dock .tool-button[title="Borracha"].active  → red glow
```

OR via `data-tool` attr (agent chooses cleanest specificity approach after reading existing cascade):

```
.uv-tools-dock .tool-button[data-tool="draw"].active    → cyan glow
.uv-tools-dock .tool-button[data-tool="erase"].active   → red glow
.uv-tools-dock .tool-button[data-tool="placeImage"].active → purple glow
.uv-tools-dock .tool-button[data-tool="placeText"].active  → cyan glow
.uv-tools-dock .tool-button[data-tool="select"].active  → neutral glow
```

**Transition:** inherit from existing `transition: box-shadow 140ms ease, transform 120ms ease, background 120ms ease` on `.tool-button` — no new transition declarations needed.

**Hover state:** unchanged (keeps existing `translateY(-1px)`).

**Focus-visible:** all tool buttons already in the focus-visible selector block — no change needed.

### JSX Edit #2 (locked)

Image tool button line 2884:
```tsx
// Before:
<button className={`tool-button`} onClick={...} title="Inserir Imagem (picker)">
// After:
<button className={`tool-button ${tool === 'placeImage' ? 'active' : ''}`} onClick={...} title="Inserir Imagem (picker)">
```

This is a className-only change — not a logic change. Permitted under the milestone "skeleton + CSS only" constraint.

### Viewport Canvas (UV-03)

**viewport-canvas** (`div.viewport-canvas`, child of `.uv-editor-viewport`):

```css
/* New rule — checkerboard background */
.viewport-canvas {
  position: relative; /* ensure ::before positions within */
}

.viewport-canvas::before {
  content: "";
  position: absolute;
  inset: 0;
  z-index: 0;
  pointer-events: none;
  background: conic-gradient(
    #141a20 25%,
    #1c242e 25% 50%,
    #141a20 50% 75%,
    #1c242e 75%
  );
  background-size: 10px 10px;
}

/* Remove debug background */
.uv-editor-viewport canvas {
  background-color: transparent; /* was rgb(10 10 10 / 60%) */
}

/* Performance-mode: suppress heavy gradient */
body.performance-mode .viewport-canvas::before {
  display: none;
}
```

Canvas `z-index: 1100 !important` and `pointer-events: auto !important` rules are **not touched**.

## Performance-Mode Contract

| Element | Normal | `body.performance-mode` |
|---------|--------|--------------------------|
| Tool glow (`box-shadow`) | Neon color glow | `box-shadow: none` (follow existing pattern — no `!important` in source rule) |
| Tool border-color | Neon color | Reset to `transparent` or `rgb(255 255 255 / 3%)` |
| Checkerboard `::before` | Visible conic gradient | `display: none` |
| Canvas background | `transparent` | `transparent` (unchanged) |
| Transitions | 140ms ease | `none !important` (existing rule already covers `* { transition: none !important }`) |

**New rules added to performance-mode block** (`after line 488`):

```css
/* Phase 4: suppress per-tool glow and checkerboard */
body.performance-mode .uv-tools-dock .tool-button.active {
  box-shadow: none;
  border-color: rgb(255 255 255 / 6%);
}
body.performance-mode .viewport-canvas::before {
  display: none;
}
```

No `!important` in these suppression rules. The existing `transition: none !important` on `* ` already covers transitions globally.

## Visual Hierarchy & Focal Points

**Primary focal point:** Active tool button — the neon glow + colored border draws the eye to the currently selected tool at all times. One button glows; others are dormant. The color identity (cyan/red/purple) lets the user identify the tool type without reading the label.

**Secondary focal point:** Canvas area — the dark checkerboard behind transparent pixels becomes the visual anchor of the canvas, communicating "edit surface" vs "content area".

**Hierarchy:** active tool glow → canvas content → dormant tools.
